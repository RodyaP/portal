# Статус версии Docker / AD

Дата: 10 ноября 2026, Екатеринбург.

## Реализовано

- Compose: PostgreSQL 16, FastAPI/Python 3.12, Nginx HTTPS, постоянный volume, healthchecks и миграция перед запуском.
- Отдельный локальный режим с HTTP только на `127.0.0.1:8080`; рабочая конфигурация требует HTTPS и Secure cookie.
- Однократная настройка локального администратора с ключом первого запуска и защитой от параллельного создания.
- Пароли локальной учётки: salted scrypt; смена и аварийный сброс оператором с завершением локальных сессий.
- Доменный вход через LDAP bind по LDAPS с обязательной проверкой сертификата и без хранения паролей сотрудников.
- Настройки AD: форма, проверка подключения, шифрование служебных реквизитов Fernet в БД, ключ вне образа.
- Роли администратора и бронирования по поручению назначаются в портале по objectGUID.
- Отзыв роли и отключение учётки проверяются при последующих запросах открытой сессии.
- Серверные сессии 8 часов, HttpOnly/SameSite=Strict cookie, проверка Origin для изменения данных, ограничение попыток входа по IP и логину.
- Аудит настроек и ролей, скрипт резервного копирования, инструкция восстановления и обслуживания.
- Восстановлены правильные расширения файлов `app.js`, `config.js`, `demo.js`.

## Проверено

- Полный набор pytest на настоящем временном PostgreSQL 16.6 в Windows: **62 passed**, без пропущенных тестов.
- Конкурентное бронирование, исключение пересечений PostgreSQL, идемпотентность, серии, права и приватность встреч.
- Первый администратор, повторный setup, локальный вход/выход, смена пароля, кириллический логин.
- Назначение и отзыв роли для действующей доменной сессии; отказ отключённой учётке.
- Ограничение попыток входа; шифрование настроек и сохранение прежнего служебного пароля при пустом поле.
- LDAP bind, экранирование LDAP-фильтров, отказ пустому/неверному паролю, обработка недоступности AD — с имитацией LDAP.
- Синтаксис JavaScript `app.js` и `access.js` проверен Node.js.
- HTTP-проверка запущенного backend: страница, JS/CSS и статус первоначальной настройки возвращают 200.
- YAML Compose разобран и проверен структурно: база/backend без опубликованных портов, локальный порт только loopback, тестовая база изолирована.
- Тестовые backend и PostgreSQL остановлены после проверки.

## Что требует проверки на целевой инфраструктуре

- Docker Engine/Compose не установлены на машине разработки: сборка образов, `docker compose config` и запуск контейнеров здесь **не выполнены**. Структурная YAML-проверка их не заменяет.
- Инструмент браузерного доступа недоступен: визуальный просмотр новых форм и интерактивный браузерный сценарий **не подтверждены**. Проверены API и синтаксис JavaScript.
- Реального подключения AD нет: нужны FQDN контроллера, DNS/сеть/VPN, CA, Base DN, служебная учётка чтения и проверка входа настоящего сотрудника.
- HTTPS-сертификат портала, серверное резервное копирование по расписанию и учение восстановления должны быть настроены при установке.
- Автоматический Windows/Kerberos SSO и импорт ролей из AD-групп не входят в текущую реализацию: используется форма доменного входа и роли портала.

В предупреждениях тестового окружения: устаревающие API используемых ldap3/Starlette и невозможность записи pytest cache из процесса другого Windows-пользователя. Ошибок тестов нет.
